# v1.1 구조 수정 계획

같은 사실을 여러 곳에서 해석·관측·판정하지 않는다. 패치는 아래 책임을 하나씩 완결하며, 기존 경로를 삭제한 뒤 다음 단계로 간다. 정확성·가독성을 먼저 확인하고 줄 예산은 마지막에 계산한다.

## 기준과 최종 구조

- 대상은 `ait-v1.1`, 기준 커밋은 `e4e28ca`. 자체 코드 6,082행, 현재 작업본 6,139행이다. 기존 entry/session 수정과 t12/t13은 보존한다. 언더테이크의 새 의미 변경은 포함하지 않는다.
- 근거는 [v1.1 명세](../ait-v1.1-spec.md), [참조 v14 명세](../ait-phase1-spec.md), [저장소 규칙](../../CLAUDE.md), Git v2.53.0 원소스 `../../../git-ref/`, 포함된 libyaml 0.2.5다. C gnu99·Git 2.53 이상을 지원·검증 기준으로 삼는다.
- 외부 바이트는 입력 경계에서 해석한다. 내부에는 범위·계약·이행 값을 전달하고, 저장·출력 경계에서만 형식화한다.
- 읽기 명령은 검사한 snapshot을 끝까지 쓴다. 쓰기는 고정된 요청을 새 T에 적용하고, CAS 재시도 때 후보와 판정을 다시 만든다.
- 전이는 각 절의 직전 계약에서, 불변식은 최종 계약·이행 view에서 판단한다. 출력은 계산한 결과를 받고 성공 행은 공개 성공 뒤에 쓴다.

```text
외부 입력 → 고정 요청
고정 요청 + T → 후보 view(계약 + 이행) → 판정 → Git 공개(CAS) → 출력
                       ↑ CAS 재시도는 새 T에서 다시 구성
```

## 패치별 구조

### 1. Git 입출력 경계 — ait.c 실행부, request.c 원격·환경 조회

- **구조:** const argv·stdin 길이·저장소 문맥·index → 기존 Git 실행 core → 바이트/종료 코드. remote는 명령별 `--` 뒤에, 환경 경로는 HEAD tree 조회 뒤 OID로 전달한다.
- **삭제:** argv→임시 strvec→child.args 이중 복사, 파일 경로를 LF 구분 cat-file 요청에 넣는 경로. 실행·자식 회수는 이미 가져온 Git 구현을 그대로 쓴다.
- **검증(t40):** remote `--dry-run`의 init/push/pull, 줄바꿈 포함 실제 환경 파일, binary stdin·상대 GIT_INDEX_FILE·네이티브 통과·stage 잠금 회귀. 새 이름 제한이나 최신 Git 전용 -Z는 추가하지 않는다.

### 2. 문법·메시지 입구 — request.c 파서, ait.c 메시지 조립

- **구조:** 옵션·절 → kind가 확정된 amend 인자 검사 → 메시지 후보의 Git trailer 검사 → 공통 상태 검사. D는 0/3개, O는 0/2개, X는 0/1개다. 계약 존재·state는 실행 판정이다.
- **메시지:** 같은 조립·검증 함수를 쓴다. 입구에서는 세 값 모두 예측 불가능한 sentinel, RID·agent·SID 확보 뒤에는 실제값으로 검사하며 fulfill의 코드 commit 전에 끝낸다. 사용자 Git 설정을 그대로 적용하고 trailer.separators=: 강제 옵션도 제거한다. 별도 임시 ODB에서 실제 `mktree → commit-tree → log`를 실행해 인코딩까지 저장 때와 같게 읽고, 필수 세 키의 개수·값을 확인한다. 임시 ODB 전체는 자식 회수 뒤 정리한다. 기록줄 가림 여부는 `interpret-trailers --parse --no-divider`가 판정하고, Git cutoff 구현은 거절된 메시지의 LINE만 찾는다.
- **삭제:** apply_clauses의 중복 문법 검사와 검증 없이 기록줄을 붙이는 경로. **검증(t41):** ait 없음·깨진 tip·무효 session보다 usage 129 우선, scissor의 정확한 LINE/hint, 정상 `---`·반복 키·-m/-F/stdin, commentChar·separator·key 설정 충돌, 거절 때 코드 commit·계약 ref·stage 무변경. 사용자 메시지 E_USAGE 129·설정 충돌 E_CONFIG 128·실제 Git 실패 E_GIT를 구별한다.

### 3. blob 판정 — contract.c map_blobs, ait.c object 응답

- **구조:** 저장 OID → 기존 cat-file 응답의 실제 type → blob일 때만 diff. BASE의 사용 불가는 한 경계에서 NOBASE로 반환하고 호출자가 명세의 문구를 고른다.
- **삭제:** 객체가 존재하면 blob으로 간주하는 판정. **검증(t42):** code/provider 기준 OID의 missing·commit·tree·blob·tag를 status/결과 틀/fulfill에서 대조한다. unverified와 E_SCOPE/hint를 유지하고 새 E_FORMAT을 만들지 않는다.

### 4. 명령의 검사된 입력 — ait.c start, status/checkout/sub/listen 초기 구독

- **구조:** 브랜치 선택 → branch T 적재·공통 검사 → 같은 branch 객체를 소비자에 전달. 이름과 only-one 표시도 같은 선택 결과를 쓴다. writer의 새 T 재판정은 유지한다.
- **삭제:** start가 이름만 반환한 뒤 branch_load로 live tip을 다시 읽는 경로. **검증(t43):** T→본문·ID가 다른 T′ 경합에서 status/초안은 T의 내용·바이트, 구독은 T의 ID를 사용한다. T′로 새로 시작한 대조군만 형식 경고/거절을 기대한다. 경고 부재만으로 통과를 판정하지 않는다.

### 5. 알림 입력 — notify.c listen_loop/receiving/deliver/event

- **구조:** 차례 시작에 V(구독·checkout·HEAD OID), N(refname·OID), remote 목록·upstream 설정을 한 번 수집한다. git remote와 for-each-ref의 objectname/refname/upstream을 사용하며 N의 저장 형식은 유지한다. branch·upstream ref는 이 입력에서 고르고 해당 OID는 N에서 찾는다. 받는 판·ref 포함·in-head도 고정값만 사용한다. 마지막 V 비교는 그 차례를 폐기할지 결정한다.
- **삭제:** 선택 뒤 새 V 붙이기, 중복 names_load/HEAD 조회, event의 live branch/ref 조회. **검증(t44):** checkout A→B, N 뒤 감시 ref·upstream 설정 이동에서 최초 선택·OID와 payload의 ref·reason·in-head 일치, 출력 성공 뒤 전달 키 즉시 .seen 기록, V 중단 때 미전달·skipped 키와 N 미확정, 사본·자기 session·되감기·upstream 삭제. 첫 사건 전달 뒤 V 중단에도 전달 키는 보존하며, EPIPE→SIGPIPE·그 밖은 fatal: write error를 유지하고 조기 파이프 종료·출력 실패를 대조한다.

### 6. 범위 값 — scope.c 입력·소유권·형식화, 모든 범위 소비자

- **구조:** 입력 한 번 → 소유한 kind·path·first/last·선택 base OID 목록. consumer/provider·구독·상태 필터·이행 code key가 이 값을 전달한다. 정렬·사상·겹침·표시는 필드를 읽는다. command/draft/stored의 허용 차이는 입력 경계가 검사한다. 절과 K=SCOPES는 값·오류를 보관하고 기존 판단 시점에 적용한다.
- **삭제:** range_of/scope_path/scope_blob를 정렬·판정·표시마다 재호출하는 문자열 경로. 진단용 원문은 값과 별도로 보존한다. 계약 복사·stage의 YAML 재해석 제거는 패치 7에서 한다.
- **검증(t15/t45):** 고정 전 중복 정체성(new/path/s/e, base 제외), 이행 키 정체성(base 포함), PATH 바이트 순·통파일 우선·행 순, 기존 tuple의 base 유지·supplied base 무시. 직렬화는 원본 순서·저장소를 바꾸지 않고 복사본은 원본 해제 뒤 유효해야 한다. 적재 후 정렬·사상·표시·겹침·판정은 좌표를 다시 해석하지 않아야 한다.

### 7. 계약·이행 값 — values.c 소유권·동등성, request.c 후보, contract.c view

- **구조:** 요청이 조건 입력·고정 stage 원본을 소유하고, 재시도 결과가 복제한 후보 계약·신규 typed fulfilment를 소유한다. 이행 조회는 신규→T 순의 함수 하나다. 같은 객체를 불변식 판정과 직렬화에 쓴다. 0단계 예정 이행과 K=SCOPES 예외는 실제 이행과 구별한다. 0단계 covered·condition-id와 신규 ID는 고정하고, 새 T에서 covered/condition-id가 다르면 E_MOVED다.
- **소유권:** spec/contract copy·clear를 짝으로 둔다. 후보의 ID·specs·목록·fulfilled source-line까지 단독 소유한다. q.files의 spec, at의 ID, old의 fulfilled를 빌려 대입하지 않는다. source-line은 동등성에서 제외하고 교체 전 값은 해제한다.
- **삭제:** struct→YAML→struct 복사, 비교용 가짜 계약, CAS마다 stage 재파싱, condition_set 포장. 실제 공개 tree의 형식 검사와 외부 merge 검사는 유지한다.
- **검증(t46):** 빈 amend·force 혼합·원복·종료 noop·배치 순서, 동일 조건을 쓰는 두 후보와 CAS 재시도의 ASan, whole O→D의 D amend+재이행 성공/D만 future amend하면 PAIR/O도 재개하면 성공. 무관한 T 변경은 같은 신규 ID로 재시도하고 covered/condition-id 변경은 E_MOVED인지 검사한다. 내부 복사·동등성·불변식 판정에 parser/emitter가 없어야 한다.

### 8. 수명 — lifetime.c 해제, contract.c 적재, notify.c 차례·사건 경계

- **구조:** 프로세스는 cat-file 자식, 요청은 고정 입력, 재시도는 후보, 알림 차례는 V·N·고정 remote/upstream·받는 판, 사건 하나는 C·첫 부모·payload·임시 diff를 소유한다. 사건 값은 다음 사건 전에 해제한다. tree entry.path 등 Git 버퍼 내부 포인터는 복제하거나 원본 소유 수명을 지킨다.
- **삭제:** 영구 tree/branch static cache와 미처리 이력 전체를 한 차례에 보유하는 경로. 새 refcount·COW·소유 flag는 만들지 않는다.
- **검증(t47+scratch):** 128 KiB 계약의 0/10/40/200회 순차 처리와 시작 전 backlog 200개, V 중단·재수신, .seen/최신 snapshot 고정 반복을 대조한다. RSS·활성 사건 판·ASan을 함께 보고, 필수 전달 기록 증가를 snapshot 누수로 세지 않는다.

### 9. 판정 결과 — contract.c judge/provider_display/touched, notify.c 선택·출력

- **구조:** 불변 view/tree의 결과는 verdict·whole witness와 사상 code·범위별 matches-any·표시 위치를 구별해 보유한다. formatter는 결과만 받는다. mutable overlay는 절마다 새로 판단하고 재귀의 visiting과 완료 결과를 구별한다. diff hunks는 동일한 순서의 blob 쌍에 한해 공유한다. 알림의 mine/HEAD 판정·구독 위치는 차례가, 과거 사건의 geometry·diff는 사건이 소유한다. 요청의 0단계 위치는 검사·결과 틀이 함께 쓰고, 최종 코드의 검사 위치로 이행 code를 구성한다. 서로 다른 index/코드 tree와 CAS 재시도는 새로 계산한다.
- **삭제:** 선택→표시의 재판정, 무관한 상대의 judge 호출, 동일 diff 반복. HEAD→index touch는 HEAD의 whole witness로 확인한 좌표를 쓴다.
- **검증(t48):** F1=(p1,q1), F2=(p2,q2), X=(p1,q2)는 unverified지만 두 범위에 ?changed 없음; X=(p1,q3)은 q만 ?changed. HEAD=F2/index=F1은 양쪽 current라도 touch. 대표 diff 6회→1회, whole witness 뒤 종료, 결과 틀 4회→1회, 이행 기록 3회→2회(서로 다른 두 시점), 한 알림 차례의 받는 판 판정 3회→1회, merge 고리·diamond·drop→amend→drop의 마지막 거절을 확인한다.

### 10. YAML 경계 — contract.c scalar writer·reader

- **구조:** libyaml이 scalar style·escaping·indentation·chomping·UTF-8을 처리한다. ait는 필드 순서·schema·허용 YAML 부분집합만 정한다. 현재 이벤트 파서를 유지한다. 두 블록 시퀀스의 scalar로 네 칸 들여쓰기를 얻고, 합성 접두사와 정확한 문서 종료 표시만 제거한다. LF 전용 정책은 reader와 writer가 같은 함수로 검사한다.
- **삭제:** 수작업 블록 허용·chomping·UTF-8 중복 검사. **검증(t49):** leading space/LF의 |2, 끝 LF·제어문자, LF 전용 원문·decoded NUL·금지 기능·원본 행, success 생략/[]·indentless 목록·빈 fulfilled 키 행. 없는 composer/loader를 전제하지 않는다.

## Git에서 무엇을 가져오고 무엇을 실행하는가

원소스 위치는 `../../../git-ref/` 기준이다. ait 계약 규칙을 Git 함수로 바꿀 수 있다고 가정하지 않는다.

| 책임 | 가져올 구조 | 사용할 구현 | 실행 명령 |
|---|---|---|---|
| 수집·판정·출력·해제 | builtin/commit.c:1655–1664의 collect→print→free | 기존 string_list·strbuf·strvec | remote, for-each-ref objectname/refname/upstream, symbolic-ref, ls-tree -z, cat-file |
| 값·수명 | remote.c:973 copy_ref, object.c:557 pool clear의 소유자 경계 | 기존 xmalloc/xcalloc/xstrdup와 list/vector/buffer clear; ait 필드 copy/clear는 ait가 작성 | 내부 복사에 Git/YAML 호출 없음 |
| 자식 실행 | run-command.c의 start→pipe→finish·cleanup | 이미 옮긴 start_command·pipe_command·finish_command, clean_on_exit·wait_after_clean을 그대로 사용 | 각 명령의 argv·stdin·환경을 전달 |
| 메시지 | trailer.c의 동일 파서로 작성값 검증 | strbuf_stripspace 재사용; wt-status.c:42–43,1100–1115의 cut_line·wt_status_locate_end를 원본대로 추가 | interpret-trailers --parse --no-divider; prefix는 stripspace --comment-lines; 문자 인코딩·설정·실제값 검사는 임시 ODB의 mktree → commit-tree → log %B·%(trailers:key=…,valueonly) |
| 저장·경합 | v1.1 4.4의 임시 index→tree→commit→CAS | 기존 tempfile 등록·정리, stage 잠금과 자식 회수 순서 유지 | update-index, write-tree, commit-tree, fetch --dry-run, update-ref old OID, diff-tree |
| 차이·인용 | builtin/diff.c의 실제 객체 타입 분리, quote.c의 셸 인용 | 기존 cat-file type과 sq_quote_buf_pretty | 명세 3.5의 고정 옵션으로 blob 두 개를 diff |

새 Git 코드는 필요한 함수·의존성만 변경 없이 옮기고 출처를 남긴다. 현재 lockfile.h는 오류 문구만 제공한다. 전체 lockfile API가 이미 있다고 가정하거나 session flock을 index 잠금으로 바꾸지 않는다.

## 바꾸지 않을 경계와 확정 정책

- 브랜치 삭제: 시작 전 부재는 거절, start 뒤 최초 T 조회 전 삭제는 현재 root 성공(t36), T 조회 뒤 CAS 전 삭제는 E_GIT 128이다. 세 시점을 보존한다. pull fast-forward에 새 형식 거절을 추가하지 않고 비 fast-forward merge 검사는 유지한다.
- **기록줄 설정 충돌:** 사용자 Git 설정을 따르고 설정 파일을 고치거나 내부에서 덮어쓰지 않는다. 정상 sentinel의 필수 기록줄을 읽지 못하면 공통 상태 검사 뒤, 코드 commit·계약 저장 전에 E_CONFIG 128로 거절하고 읽히지 않은 키와 확인한 충돌 원인을 알린다. 명세 4.5·4.8에 반영했다(U52). 실제 scissor는 E_USAGE 129, Git 명령 자체의 실패는 E_GIT다. 기록줄 가림 여부는 Git 파서가 판정하고, 옮긴 cutoff 함수는 오류의 LINE만 찾는다. `auto`는 `interpret-trailers`·`log`처럼 `#`로 취급한다. commentChar/commentString의 유효 prefix는 설치된 Git의 `stripspace --comment-lines`로 받아 설정 우선순위를 재구현하지 않는다.

## 검증과 마지막 줄 예산

- 각 동작 오류는 수정 전 RED→수정 후 GREEN으로 확인한다. 구조 정리는 출력·ID·오류 우선순위·소유권과 제거된 재해석/재관측/재판정으로 검증한다.
- 검증은 사용자 지정 Git 2.53.0으로 실행한다. 관련 회귀 뒤 전체 `JOBS=6 make test`·`git diff --check`, 기존 entry/session과 통합 검증을 마친다. 독립 검수 제안도 원자료·재현으로 다시 확인한다.
- 마지막에 helper·호출자·선언을 합쳐 자체 코드 3,900행 상한을 계산한다. 이동·압축·외부 코드 재분류를 절감으로 세지 않는다. 남는 간극은 수치와 원인으로 적는다.

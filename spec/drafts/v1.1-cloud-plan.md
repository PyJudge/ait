## 2. 규칙(한 문장)

**VM은 setup script로 git을 갖추고, 저장소는 자기 계약에 맞는 ait를 싣고 다니며 SessionStart hook이 그것을 설치한다.**

- git은 VM의 도구다. 문서가 setup script의 자리로 정한 것(툴체인)이고, 찍어 둔 판이 다시 쓰이므로 세션마다 내려받지 않는다.
- ait는 저장소의 계약 형식과 판이 맞아야 한다. 그래서 저장소가 판을 고정해 싣는다. 문서가 SessionStart hook의 자리로 정한 것(프로젝트 준비)이다.

## 3. ait 빌드 (Linux x86_64)

1. 이 Mac의 Docker에서 `ubuntu:24.04`(linux/amd64) 컨테이너를 쓴다. 클라우드와 같은 배포판·glibc다.
2. 그 안에서 `make`로 빌드한다. Linux에서는 Makefile이 이미 `-DHAVE_GETRANDOM`을 쓰고 iconv를 링크하지 않는다. 바이너리가 기대는 것은 glibc뿐이다. v1.1은 아직 Linux에서 한 번도 빌드하지 않았다.
3. 같은 컨테이너에 4장의 git을 깔고 `make test` 전체를 돌린다. 클라우드와 같은 git 판에서 통과해야 배포한다.
4. `make bundle`의 이름이 플랫폼마다 겹치지 않게 한다. 지금은 macOS와 Linux 묶음이 모두 `dist/ait-v1.1.tar.gz`다. Linux 묶음은 `dist/ait-v1.1-linux-x86_64.tar.gz`로 둔다(`PLATFORM` 파일은 이미 `uname -sm`을 적고 `install.sh`가 그것을 검사한다).
5. 내려받을 것(사용자 승인이 필요하다): Docker Hub의 `ubuntu:24.04` amd64 이미지(약 30 MB), 컨테이너 안의 `gcc`·`make` 패키지(archive.ubuntu.com), 4장의 git.
6. arm Mac에서 amd64 컨테이너는 에뮬레이션으로 돈다. 시험 76개는 몇 배 느릴 수 있다.

## 4. 클라우드의 git

환경 설정의 **Setup script**에 넣는다(사용자가 claude.ai의 환경 설정 창에서 넣는다).

```bash
#!/bin/bash
set -e
# git-core PPA: ait needs git 2.53 or later; Ubuntu 24.04 has 2.43
install -d -m 0755 /etc/apt/keyrings
curl -fsSL 'https://keyserver.ubuntu.com/pks/lookup?op=get&search=0xE1DD270288B4E6030699E45FA1715D88E1DF1F24' |
	gpg --dearmor -o /etc/apt/keyrings/git-core.gpg
echo 'deb [signed-by=/etc/apt/keyrings/git-core.gpg] https://ppa.launchpadcontent.net/git-core/ppa/ubuntu noble main' \
	> /etc/apt/sources.list.d/git-core.list
apt-get update
apt-get install -y git
git --version
```

- `add-apt-repository`는 `api.launchpad.net`에 묻는데, 그 호스트는 허용 목록에 없다. 그래서 목록 파일과 키를 직접 둔다. 키는 `keyserver.ubuntu.com`(허용 목록의 `*.ubuntu.com`)에서 받는다.
- **확인 필요**: 키 지문(`E1DD2702…E1DF1F24`)은 Claude가 기억으로 적은 것이다. 처음 돌릴 때 `apt-get update`가 서명을 받아들이는지로 확인한다.
- PPA가 주는 판은 지금 2.54다. 7장의 질문 3.

## 5. 저장소가 싣는 ait

criminal-decision-draft(또는 ait를 쓰는 저장소)에 둔다.

```
tools/ait/            Linux 묶음을 푼 것(bin/ait, skills/, install.sh, VERSION, PLATFORM)
scripts/cloud-ait.sh  클라우드에서만 ait를 설치한다
.claude/settings.json SessionStart hook
```

`scripts/cloud-ait.sh`:

```sh
#!/bin/sh
# cloud sessions only (CLAUDE_CODE_REMOTE); the repository pins the ait its contracts are written for
[ "$CLAUDE_CODE_REMOTE" = true ] || exit 0
PREFIX=/usr/local sh "$CLAUDE_PROJECT_DIR/tools/ait/install.sh" >&2
```

`.claude/settings.json`의 hook:

```json
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup|resume",
        "hooks": [{ "type": "command", "command": "sh \"$CLAUDE_PROJECT_DIR/scripts/cloud-ait.sh\"" }]
      }
    ]
  }
}
```

- `install.sh`는 같은 바이너리면 복사하지 않으므로 재개할 때 드는 시간은 비교 하나다.
- 묶음은 git 2.53 미만이면 설치를 거절한다(`install.sh`). setup script가 실패해 git이 낡으면 세션 시작에서 그 사실이 보인다.
- 저장소의 `.claude/skills/`에 있는 스킬은 지금 v2의 것이다. 옮길 때 묶음의 v1.1 스킬로 바꾼다(`setup.sh`가 둔다).

## 6. 계약이 VM 밖에 남는 길

VM은 세션마다 새것이고 회수된다. 계약은 GitHub의 `ait/*` 브랜치에만 남는다.

1. 클론에 `origin/ait/<name>`이 오는지, `ait init`이 그것을 받아 로컬 `ait/<name>`을 만드는지(규격 6.1).
2. 요청·이행 뒤 `ait contract push`가 GitHub 프록시를 지나 `ait/<name>`을 갱신하는지. 프록시가 세션 브랜치 밖의 push를 막으면 계약은 VM과 함께 사라진다.
3. 두 세션이 같은 계약 브랜치를 push하면 뒤의 것은 non-fast-forward로 거절되고, `ait contract pull`이 합친 뒤 다시 push한다(규격 6.5.6).
4. 다른 세션의 변경은 `ait listen --fetch <초>`로 받는다.

스킬은 이미 "원격과 주고받을 때는 계약 브랜치의 Git upstream을 준비한다"와 `contract push`를 말한다. 클라우드에서는 **요청과 이행마다 push한다**는 한 줄이 더 든다(VM이 회수되기 때문이다).

## 7. 정할 것

1. **올릴 판**: criminal-decision-draft는 아직 v2다(`.ait/init`이 `version 2`, 계약이 코드 브랜치의 `.ait/`에 있다).
   - (a) v1.1을 올린다. 먼저 그 저장소를 v1.1로 옮긴다(옮기기 계획은 따로 남아 있다). 추천: v2는 분리해 얼려 두었고, 두 번 일하지 않는다.
   - (b) 지금은 v2를 올린다(`../ait-v2`를 Linux로 빌드). 옮긴 뒤 다시 바꾼다.
2. **ait를 싣는 방법**:
   - (a) 빌드한 묶음을 저장소에 커밋한다(5장). 추천: 판이 저장소와 함께 고정되고 네트워크가 필요 없다. 바이너리 하나(수백 KB)가 이력에 남는다.
   - (b) GitHub release의 첨부로 두고 hook이 받는다. 이력은 가볍지만 판을 따로 맞춰야 하고, 비공개 저장소의 첨부가 프록시로 받아지는지 확인해야 한다.
   - (c) 소스를 싣고 VM에서 빌드한다. 바이너리는 없지만 세션마다 빌드 시간이 들고 소스 전체가 저장소에 들어간다.
3. **git 판**: 규격 6.1-1은 2.53 이상을 받고, 검증은 2.53에서 했다.
   - (a) PPA의 최신(지금 2.54)을 쓰고, 3장의 3에서 그 판으로 `make test` 전체를 돌린다. 추천: setup script가 짧고 보안 갱신을 받는다.
   - (b) 2.53을 소스(archive.ubuntu.com의 26.04 소스 패키지)에서 빌드한다. 검증한 판과 같지만 setup script가 길어 5분 안에 끝나는지 재야 한다.

## 8. 확인 순서 (결정 뒤)

1. 로컬: 3장의 빌드와 `make test`(7장 3의 git 판).
2. 클라우드 세션 하나: setup script → `git --version` ≥ 2.53 → hook → `command -v ait` → `ait init` → `ait status /`.
3. 같은 세션: 시험 계약 하나를 `future demand`로 만들고 `ait contract push` → GitHub에서 `ait/<name>`이 바뀌었는지(6장의 2).
4. 같은 세션: `ait fulfill`이 클라우드의 git 설정(서명 프록시, 커밋 hook, 기록줄)에서 커밋하고 기록하는지(규격 4.5의 기록줄 되읽기).
5. 두 번째 세션: 같은 브랜치에 요청 → push 거절 → `contract pull` → push(6장의 3), 그리고 첫 세션의 `listen --fetch`가 받는지.

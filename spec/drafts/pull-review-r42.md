## 0. 원인

깨진 곳은 원인이 넷이다.

1. **명세 파일을 pull이 git 대신 합쳤다.** 같은 장치를 r27, r30, r33, r36, r39, r42의 여섯 번 고쳤다. git merge가 이미 정해 둔 것(양쪽, 지우기, rename, merge base, 여러 끝의 차례)을 ait가 하나씩 다시 정의했고, 검수마다 그다음 하나가 나왔다. 이번에는 다음 지적들이 이 원인이다.
   - 끝이 여럿일 때 다시 분류(Codex B F2, Claude B H1)
   - 셋째 끝 누락(Codex A P1)
   - 형식이 틀린 판 읽기(Codex B F1, Claude B L2)
   - 들이는 쪽 사고(Claude B M2)
   - MF2의 범위(Claude A L2)
   - 공유 명세(Claude A L3)
2. **마치는 커밋의 hook 규칙을 v14 7.1.3에 조각으로 덧댔다.** 그래서 다시 고정의 `prev`가 정해지지 않았다(Claude A H1, Claude B H2). HEAD의 사고와 레코드마다 보는 7.1.3-4도 부딪혔다(Claude A M2).
3. **나눠 받기 hint를 결정 20 대신 Claude가 고른 목표 상태로 썼다.** 이미 참인데도 막히는 경우가 나왔다(Claude B M1). 결정 20과도 다르다(Claude A M3). 명령의 차례·단위도 정하지 않았다(Claude A M4, Claude B M4·L1).
4. **TIE가 해시로 고를 때 되돌린 쪽이 해시로 바뀐다**(Claude A M1, Claude B M3). 사용자에게 물었다(결정 30).

## 2. 고친 것

pull-decisions.md의 결정 30, 기록 107~113에 적었다.

- **명세 파일(기록 107):** ait는 받지 않을 변경만 정한다. 판정 차례는 개정 8과 같다. 그 변경은 git에 넘기기 전에 그 쪽에서 빼고, git이 코드와 함께 합친다. 범위는 "그 쪽에서 계약이 고정한 파일"(v14 규칙 3)이다.
- **바뀌는 기대:** PV1은 충돌이 없어진다. MF2의 `specs/w.yaml`은 들어오지 않는다. 둘 다 버린 판의 명세를 받지 않는다는 규칙을 예외 없이 따른 결과다.
- **마치는 커밋(기록 108):** 다시 고정은 그 판 위에 얹는다. index 판이 HEAD 판 그대로면 v14대로 지난다.
- **나눠 받기(기록 109):** 단위는 함께 받아야 하는 끝의 묶음이고, 차례는 각 명령이 멈추지 않는 차례다. 그런 차례가 없으면 결정 20의 상태를 쓴다. 결정 26의 멈춤은 XT1에서 빼지 않는다.
- **되돌린 커밋(기록 110):** 필요한 blob이 없으면 세지 않는다. 5절의 1.5d 목록을 채웠다.
- **TIE(결정 30):** 내 판을 포함하는 판의 커밋을 먼저 고른다. RP6의 기대가 바뀐다(되돌린 쪽은 x).
- **글과 스크립트(기록 111~113).**
